1. Ensure base app entry exists at `src/main.tsx`: it creates the TanStack Router instance from the generated `src/routeTree.gen.ts`, renders `RouterProvider` into `#root`, and imports `src/styles/global.css` exactly once. Expected outcome: app boots with routing active and Tailwind styles applied.

2. Ensure `src/styles/global.css` contains exactly `@import "tailwindcss";` as its first line and nothing else unless a later step requires it. Expected outcome: Tailwind v4 utilities available app-wide.

3. Ensure `vite.config.ts` registers the TanStack Router plugin (`@tanstack/router-plugin/vite`), the React plugin, and the `@tailwindcss/vite` plugin, plus the `@/` path alias mapping to `src/`. Expected outcome: routes are generated automatically and `@/` imports resolve.

4. Create/confirm the app shell at `src/routes/__root.tsx`: a root route rendering only an `Outlet` inside a full-height wrapper (`min-h-screen`) with the page background and default text color classes described in step 6. No nav bar, no header, no footer — the app is intentionally single-screen. Expected outcome: every route inherits the background and fills the viewport.

5. Create the home route at `src/routes/index.tsx` for the `/` URL. It renders a single centered section containing:
   - an `h1` with the text `Hello, World!`
   - a short muted subtitle line beneath it, e.g. a one-sentence welcome
   Expected outcome: visiting `/` shows the greeting and nothing else.

6. Apply the visual design using Tailwind utility classes only (no CSS modules, no inline style objects):
   - Layout: outer wrapper uses flex, `items-center`, `justify-center`, `min-h-screen`, horizontal padding around `px-6`, and `text-center`.
   - Content stack: a max-width container (~`max-w-xl`) with vertical spacing between headline and subtitle of roughly `space-y-4`.
   - Headline: large responsive size stepping from about `text-4xl` on mobile to `text-6xl` at the `sm`/`md` breakpoints, `font-semibold` or `font-bold`, tight tracking (`tracking-tight`), and balanced line wrapping.
   - Subtitle: around `text-base` to `text-lg`, normal weight, muted color, comfortable `leading-relaxed`.
   - Colors (light mode): near-white/slightly warm background such as a `slate-50`/`zinc-50` tone, headline in a near-black slate tone, subtitle in a mid slate/zinc tone.
   - Colors (dark mode): via `dark:` variants — deep slate/zinc-950 background, off-white headline, mid-light slate subtitle. Verify contrast in both modes.
   - Subtle background treatment: a soft vertical gradient (e.g. `bg-gradient-to-b` between two adjacent neutral shades) or a faint radial glow behind the content. Keep it low-contrast and non-distracting; it must not reduce text legibility in either mode.
   - Typography: rely on the Tailwind default sans stack, or optionally set a single system-friendly sans font family on the root wrapper. Do not add webfont loading for this scope.

7. Confirm no extra surface area is introduced: no additional routes, no components in `src/components/`, no hooks, no data fetching, no state, no auth, no backend calls. Expected outcome: the diff stays limited to the entry, styles, config, root route, and index route.

## Verification checklist
1. `npm run dev` starts without TypeScript or Vite errors.
2. Navigating to `/` renders `Hello, World!` with the subtitle below it.
3. Content is vertically and horizontally centered at desktop, tablet, and narrow mobile widths with no horizontal scrollbar.
4. Headline scales down gracefully on small screens and never wraps awkwardly mid-word.
5. Toggling the OS/browser color scheme to dark swaps background and text colors, and text remains clearly readable in both modes.
6. `src/routeTree.gen.ts` was regenerated by the plugin and was not hand-edited.
7. Browser console shows no warnings or errors on load.
